# Лабораторная работа 3. "Печать графиков"

## 1. Постановка задачи

Требуется разработать desktop‑приложение на C++ с использованием библиотеки Qt, которое позволяет:

- Отображать иерархическую структуру файловой системы (папки) в левой панели.
- Показывать список файлов в выбранной папке.
- Загружать данные из двух типов источников:
  - SQLite (файлы .sqlite) – таблица должна содержать колонки Time  и Value.
  - JSON (файлы .json) – корневой массив объектов с полями date  и value.
- Применять к графику цветовую или чёрно‑белую стилевую схему.
- Сохранять текущий график в PDF через стандартный диалог сохранения файла.
- Обрабатывать ошибки загрузки, отсутствие данных, неверные форматы и информировать пользователя.

## 2. Предлагаемое решение

### 2.1 Общая идея

Система строится на основе архитектурных паттернов, обеспечивающих гибкость, расширяемость и слабую связанность компонентов:

- Модель‑Представление-контроллер (Model‑View-Controller) – отделение данных (ChartModel) от виджетов отображения (ChartWidget, таблицы).
- Адаптер (Adapter) – унификация доступа к разным источникам данных (IDataLoader) и разным типам графиков (IChartAdapter).
- IoC контейнер (Inversion of Control) – централизованное управление зависимостями, регистрация и получение экземпляров адаптеров.

Приложение реализовано как однооконное с разделителем (QSplitter): слева – дерево папок, справа – список файлов, органы управления, область графика и таблица данных.

### 2.2 Ключевые сущности (классы и интерфейсы)

IDataLoader - Абстрактный загрузчик данных. Метод load(sourcePath, tableName) возвращает QVector<QPointF>. 
SQLiteLoaderAdapter - Реализация загрузки из SQLite. Читает таблицу с колонками Time и Value. 
JsonLoaderAdapter - Реализация загрузки из JSON. Ожидает массив объектов {"date": "...", "value": ...}. 
ChartModel - Хранит загруженные данные, управляет их очисткой. Сигнализирует об изменениях, ошибках. 
IChartAdapter - Адаптер создания виджета графика заданного типа. Метод createChartWidget(data) возвращает QWidget*. 
LineChartAdapter, BarChartAdapter - Создают ChartWidget, устанавливая тип "line" или "bar". 
ChartWidget - Основной виджет отрисовки графика. Содержит логику вычисления масштаба, рисования осей, сетки, линий/столбцов. 
IStyleStrategy - Интерфейс стратегии цветового оформления. Методы getBackgroundColor(), getSeriesColor() и т.д., а также apply(QWidget*). 
ColorStyle, GrayscaleStyle - Конкретные стратегии: цветная и чёрно‑белая гамма. 
IOCContainer -  IoC‑контейнер (реализация на шаблонах). Позволяет регистрировать фабрики или синглтоны интерфейсов. 
MainWindow - Главное окно, содержит инициализацию UI, соединения сигналов/слотов, вызовы контейнера для получения адаптеров, обработку выбора файла, печать PDF. 
DataTableModel (внутри MainWindow.cpp) - Вспомогательная модель QAbstractTableModel для отображения данных графика в таблице.

### 2.4 Применённые паттерны проектирования

#### 2.4.1 Паттерн Адаптер (Adapter)

Назначение: преобразует интерфейс одного класса в интерфейс, ожидаемый клиентом. Позволяет классам работать вместе, что было бы невозможно из‑за несовместимости интерфейсов.

Применение в проекте:

- IDataLoader – клиент (ChartModel) ожидает единый метод load(...), возвращающий QVector<QPointF>. Конкретные адаптеры (SQLiteLoaderAdapter, JsonLoaderAdapter) скрывают детали работы с SQLite и JSON.
- IChartAdapter – клиент (MainWindow) не создаёт виджеты графика напрямую, а получает их через адаптер. LineChartAdapter и BarChartAdapter настраивают ChartWidget соответствующим типом.

#### 2.4.2 Паттерн Стратегия (Strategy)

Назначение: определяет семейство алгоритмов, инкапсулирует каждый из них и делает их взаимозаменяемыми. Стратегия позволяет изменять алгоритм независимо от клиентов, которые его используют.

Применение в проекте:

- Интерфейс IStyleStrategy объявляет методы получения цветов и применения к виджету.
- Конкретные стратегии ColorStyle и GrayscaleStyle реализуют разные цветовые схемы.
- Пользователь переключает стиль через QCheckBox. При изменении состояния MainWindow регистрирует новую стратегию в контейнере и перерисовывает график через вызов style->apply(m_chartWidget).

#### 2.4.3 Паттерн IoC (Inversion of Control)

Назначение: централизованное управление зависимостями. Объекты не создают зависимости внутри себя, а получают их извне (контейнер).

Применение в проекте:

- В MainWindow::registerDependencies() регистрируются:
  - IChartAdapter – по умолчанию LineChartAdapter.
  - IStyleStrategy – по умолчанию ColorStyle.
- При изменении типа графика или стиля контейнер перенастраивается через RegisterInstance.
- При печати PDF контейнер предоставляет актуальный адаптер и стратегию:  
  auto adapter = gContainer.GetObject<IChartAdapter>(); 
  auto style = gContainer.GetObject<IStyleStrategy>();

## 3. Инструкция пользователя

### 3.1 Рабочий интерфейс

- Левая панель – дерево папок. Нажмите на любую папку, чтобы показать её содержимое в правой верхней таблице.
- Правая верхняя таблица – список файлов в выбранной папке. Отображаются только файлы с расширениями `.sqlite`, `.json`.
- Панель управления – под таблицей файлов:
  - Выпадающий список «Тип графика»: Линейный или Столбчатый.
  - Флажок «Черно-белый график» – переключает цветовую схему.
  - Кнопка «Печать графика» – сохранение текущего графика в PDF.
- Область графика – отображает загруженные данные в выбранном стиле.
- Таблица данных – внизу показывает список точек (порядковый номер, дата, значение).


### 3.2 Последовательность работы

1. Выберите папку, где лежит файл данных.
2. В таблице файлов кликните по нужному файлу – данные автоматически загрузятся, и появится график.
3. При необходимости переключите тип графика или цветовую схему – график мгновенно обновится.
4. Чтобы сохранить график в PDF, нажмите «Печать графика», укажите имя файла (расширение .pdf).
5. В случае ошибки (неверный формат, пустой файл, отсутствие таблицы) появится сообщение, и статусная строка покажет ошибку.

## 4. Тестирование

### 4.1 Процесс тестирования

Тестирование проводилось вручную и с использованием сценариев, охватывающих как корректные, так и некорректные входные данные. Каждый тестовый случай проверял:

- Загрузку данных из SQLite/JSON.
- Отображение графика (линейный / столбчатый) и таблицы.
- Переключение стилей.
- Сохранение PDF.
- Реакцию на ошибки (отсутствие файла, пустой файл, неверная структура, неверные типы данных).

### 4.2 Реакция на недопустимые действия

- Некорректный путь – при выборе файла через таблицу путь всегда корректен.
- Изменение размера окна – график корректно масштабируется за счёт пересчёта в paintEvent.

### 4.3 Выводы по тестированию

Приложение стабильно работает во всех протестированных сценариях. Все архитектурные решения (адаптеры, стратегии, IoC) не мешают, а, наоборот, упрощают добавление новых типов графиков или загрузчиков в будущем. Обработка ошибок информативна для пользователя. Графическая часть соответствует требованиям задания.
